# Playbooks

These playbooks provision the lab, perform backups to your local machine, and reset the SONiC nodes.

## Provision the Lab

The following Ansible playbooks (scripts) were used to configure the lab from scratch.

You can use them to redeploy the configuration to the environment, should you wish to make changes, try out some new config, or just learn how the lab is configured. You can safely rerun them even on an already configured lab, but beware they will overwrite any existing config.

### configure_servers.yml
This script configures the Ubuntu servers as if they were completely unconfigured. You can run this script multiple times if needed.

### configure_sonic.yml
This script configures the SONiC spine and leaf switches as if they were completely unconfigured. You can run this script multiple times if needed, but beware to overwrite any existing config. 

This script configures SONiC in [split-unified](https://github.com/sonic-net/sonic-buildimage/blob/master/src/sonic-yang-models/yang-models/sonic-device_metadata.yang#L58) mode. This means that FRR configuration is NOT generated by ConfigDB and all config is placed into a single `etc/sonic/frr/frr.conf` file.


## Optional Scripts
The following scripts perform optional tasks should you need. They are not required to run for the lab to work. 

### backup_servers.yml
This script copies server configuration into local config files. 

### backup_sonic.yml
This script copies SONiC leaf and spine configuration into local config files for split-unified mode (default).

### configure_sonic_split_mode.yml
This script configures the SONiC spine and leaf switches as if they were completely unconfigured. You can run this script multiple times if needed, but beware to overwrite any existing config.

This script configures SONiC in [split](https://github.com/sonic-net/sonic-buildimage/blob/master/src/sonic-yang-models/yang-models/sonic-device_metadata.yang#L58) mode. This means that FRR configuration is NOT generated by ConfigDB and all config is placed into multiple files in the `etc/sonic/frr/` directory.

This is an optional way to configure the SONiC nodes. Depending on the environment, an organization may find this easier to manage, but typically split-unified is implemented as it only deals with one file. 

### reset_sonic.yml
This script removes all routing configuration (both split and split-unified) on the SONiC spine and leaf nodes. It does NOT remove any config from the servers.

It removes `/etc/sonic/config_db.json`, `/etc/sonic/frr/bgpd.conf` and `/etc/sonic/frr/frr.conf`. Then it reboots the system.
